# TestDriver Setup for Square Open Source Portal

## Step 1: Create GitHub Actions Workflow

Create `.github/workflows/testdriver.yml`:

```yaml
name: TestDriver Tests

on:
  pull_request:
  push:
    branches: [master]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      # Build the Jekyll site
      - name: Setup Ruby
        uses: ruby/setup-ruby@v1
        with:
          ruby-version: '2.7'
          bundler-cache: true
      
      - name: Build Jekyll site
        run: |
          bundle install
          bundle exec jekyll build
      
      # Serve the built site
      - name: Start Jekyll server
        run: |
          bundle exec jekyll serve --detach --port 4000
          sleep 5
        
      # Run TestDriver tests
      - name: Run TestDriver Tests
        env:
          TESTDRIVER_API_KEY: ${{ secrets.TESTDRIVER_API_KEY }}
          TD_WEBSITE: "http://localhost:4000"
        run: |
          npm install -g testdriverai@latest
          npx testdriverai run .
```

## Step 2: Initialize TestDriver

Run the initialization command:

```bash
npx testdriverai@latest init
```

When prompted, enter `http://localhost:4000` as your website URL.

## Step 3: Set Environment Variables

Add your TestDriver API key to GitHub Secrets:
1. Go to Settings > Secrets and variables > Actions
2. Click "New repository secret"
3. Name: `TESTDRIVER_API_KEY`
4. Value: Your API key from TestDriver dashboard

## Step 4: Generate Exploratory Tests

Create initial exploratory tests:

```bash
npx testdriverai generate web 5
```

This generates 5 exploratory test prompts focusing on:
- Repository listing and navigation
- Category filtering functionality
- Link validation
- Responsive design
- Search and filtering features

## Step 5: Convert to Regression Tests (Optional)

After reviewing exploratory tests, convert them to regression tests:

```bash
npx testdriverai generate web 5 --write
```

## Local Testing

To test locally before pushing:

```bash
# Start Jekyll server
bundle exec jekyll serve

# In another terminal, set environment variable and run tests
export TD_WEBSITE="http://localhost:4000"
npx testdriverai run .
```

## Rationale

This approach is recommended for the Square Open Source Portal because:

1. **Static Site Architecture**: The site is built with Jekyll, which generates static HTML. The GitHub Actions workflow properly builds the site first using `bundle exec jekyll build`, then serves it, matching the project's existing development workflow.

2. **Existing Build Process**: The repository already has a Travis CI setup (per .travis-ci.org badge), so we're following established patterns by using GitHub Actions for CI/CD. The build happens in CI before TestDriver runs.

3. **No Local Building in Lifecycle Files**: The provision.yaml only launches Chrome and navigates to the pre-built site via TD_WEBSITE environment variable. All building happens in the GitHub Actions workflow.

4. **Repository-Focused Testing**: The site's primary purpose is displaying Square's open source repositories with filtering and navigation. Tests should focus on:
   - Repository cards loading correctly
   - Category filtering functionality
   - External links to GitHub repositories
   - Responsive layout across devices
   - Image loading for repository logos

5. **Simple Deployment**: Since it's a static site, we can serve it locally with Jekyll's built-in server for testing, making the setup straightforward and fast.

6. **Environment Variable Pattern**: Using TD_WEBSITE allows the same tests to run against localhost (CI), staging, or production by simply changing the environment variable value.
